1.11.0 (231)

- Importing several files at once no longer closes before the last file, and a later import in the same session no longer closes after its first file
- New per-server "Default upload tags" setting in Preferences: the chosen tags are preselected when uploading a document, including from the share sheet
- Task results and error messages show up again on Paperless-ngx v3, including files rejected as duplicates
- Documents with duplicates now say so: on Paperless-ngx v3 a document that shares its file content with others shows them in its details, and you can open them from there
- New "Duplicates" filter for documents with or without duplicates, on Paperless-ngx v3.2 and later
- Items in the Settings lists and Trash now stay in place until a delete succeeds, so a failed delete no longer hides them
- Swipe-to-delete in a searched Settings list now deletes the item you swiped
- New installs start with a short welcome page before the login screen, explaining that the app needs your own Paperless-ngx server
- What's New can now show a paged overview of a release, with an icon and a short description per feature and more detail on request; versions without one keep showing the release notes
- A "Leave a tip" link in the release notes now opens the tip jar in the app
- Nested tags in Settings now show delete buttons in edit mode
- Failed loads now retry on their own when a VPN such as Tailscale connects, and for about a minute after the app opens or returns to the foreground
- Long tag names in a document's tag editor are now cut short to fit, instead of widening the sheet and clipping every tag and the add buttons
- The share extension's fields are no longer cut off at the bottom on iPad
- Picking a correspondent, document type or storage path from a search in the add-document form now closes the search and keyboard
- Uploading and logging in with a username and password now work on servers that sign you in automatically (PAPERLESS_AUTO_LOGIN_USERNAME), instead of failing with "CSRF token missing"

1.11.0 (229)

- Keeping a document or saved view offline now downloads it and its text right away on any connection, including cellular data and Low Data Mode. Keeping a saved view on such a connection says so before you confirm

1.11.0 (228)

- New "Keep offline" action on documents: a kept document's PDF is downloaded right away and stays on the device whatever the offline browsing mode, is never removed by the storage budget, the list trim or switching back to "Recently browsed", and follows new versions from the server. The new "Kept offline" view in the saved view selector lists them, and the Offline & Sync screen shows how many of their files are on the device

1.11.0 (227)

- A document whose PDF is already downloaded now opens with it straight away, even when the server takes a while to answer. A small spinner next to the page count shows while the app checks the server for a newer copy, which replaces it if there is one
- A downloaded document whose details changed on the server, for example a new tag or title, is no longer downloaded again when you open it: the app asks the server whether the file itself changed and keeps its copy if not
- With "Entire library" offline browsing, the PDF of every document is now downloaded ahead of time, so documents open offline without ever having been viewed. The downloads run in the background and continue while the app is closed, stay on Wi-Fi unless "Sync over cellular" is on, pause when the device is low on storage, and are removed when you switch back to "Recently browsed". The Offline & Sync screen shows how many files are on the device and how many are downloading

1.10.4 (226)

- On iPhone Duo's inner display, the document list now sits beside the open document, and the list and document stay put when you fold or unfold the phone
- The app now rotates to landscape on iPhone Duo's outer display
- Fix PDF pages and the filter bar sitting under the side toolbar on iPhone Duo
- On iPad, the edit panel now starts closed so it doesn't cover the document; the toolbar button opens it
- The iPad split view keeps the columns you chose after a trip through narrow Split View or Slide Over
- On iPad you can now refresh an open document from the toolbar, picking up a new version or changed details without closing and reopening it

1.11.0 (225)

- A new "Upload Document" action in the Shortcuts app uploads a file to Paperless without opening the app, letting you automate uploads. You can pick the target server, and optionally set a title, document type, correspondent and tags; leaving the title empty lets the server derive one from the filename
- "Last refreshed" on the Offline & Sync screen now keeps its value when the app is restarted, instead of showing "Never" until the next refresh
- Switching away from the app while it is syncing no longer cuts the sync off: it gets some time to finish in the background, and stops cleanly if that time runs out
- Offline data now refreshes in the background, even when you haven't opened the app for a while. With "Entire library", the full download also continues in the background, mostly overnight. This needs Background App Refresh to be on for the app
- The debug menu now has a "Sync runs" screen listing what each recent sync did, step by step, and how it ended, including background runs
- Documents you have opened are kept for offline use within a 500 MB budget: once it is full, the ones you opened longest ago are removed first. Files that no longer belong to any cached document are cleaned up at launch and when a server is removed, and the debug menu shows what each cleanup did
- Thumbnails are now stored alongside the downloaded document files and removed with them, instead of in a separate cache that could drop them at any time; the Offline & Sync storage figures now come from the app's own records of what it has downloaded

- Pulling to refresh a document whose preview or original file failed to download now tries the download again, instead of staying on the error until the document is reopened
- A change the server has saved is no longer reported as failed when the app cannot update its local copy right away; the local copy catches up on its own
- The document list no longer briefly says you have no documents while it is still loading on launch
- A deleted document no longer reappears in a document list, as an empty placeholder or as a document that still opens, when a list update was running at the moment it was deleted

- The Offline & Sync screen now lists which parts of the last sync failed and why, clearing each as it succeeds again. Being offline doesn't count as a failure, so syncing without a connection no longer marks every saved view as failed
- Turning off "Entire library" offline browsing now stops the download already in progress, instead of letting it carry on re-downloading data that was just removed
- The Offline & Sync screen now shows how much space the offline data takes up on your device: the database, downloaded documents and thumbnails

1.11.0 (217)

- Opening a document whose PDF is already cached now shows it immediately, even on a slow connection, instead of waiting behind a loading spinner
- Pulling to refresh an open document now picks up a new version added on the server, instead of continuing to show the previous one until you close and reopen it

- Connection errors now say what went wrong: that your device is offline, that the server's address can't be found, that the server isn't responding, or that the connection dropped, instead of a generic error. Timeouts while signing in are reported the same way
- When a document list can't be loaded, for example after changing the filter or switching saved views while the server is unreachable, the list now says so and offers to retry, instead of showing "No documents". A list that only partly loaded shows a notice above the documents it has

# Limited permissions support

This build introduces the support for limited permissions in the app. Previously, the app would simply throw errors that resulted from API errors on operations that the currently logged in user lacked permissions for.

For example, editing a document without the document edit permissions would simply throw an error that the operation could not be completed. For viewing, this resulted in very frequent errors, as the app periodically refreshes some information.

Now, the app can now work with a minimal set of permissions and will present missing permissions in the UI before errors are being thrown.

Here comes the important bit: I need your help to ensure this doesn't break some workflow or some scenario which I didn't test. For example, if anything is not accessible, a button is greyed out or anything does not behave correctly, even though from you permissions situation you would expect that it does, **please report an issue**, either via E-Mail or on GitHub on [this issue](https://github.com/paulgessinger/swift-paperless/issues/115).

# Custom fields edit support
Custom fields can now be edited on documents. I put in a validation layer to prevent saving of incorrect values.

# What's new?

- All new login screen with a new design
  - Improved error handling with more detailed error messages in many scenarios
  - Added the ability to log in with a token or without credentials (auto-auth,
    mTLS, etc)
- Added the ability to change servers when the currently active server is not responding.
- Added shortcut to create a bug report on GitHub from the settings
- Recover from invalid filter rule contents (set manually in the admin backend)
in certain cases
- Explicit handling and detection of unsupported server API versions
  - The server details in the settings now report if the server is running an
    unsupported version
- Added warning when using the `Authorization` header as a custom header
- Improved error output when API response parsing fails
- Add option to log out or switch servers on the loading screen. This is shown
  after a short timeout
- Clarify what the top toolbar dropdown menu means if now saved views exist
- Fix an issue when sharing exported logs via share sheet
- Add ability to swipe down to hide the bottom bar in the document detail view.
  Added a setting to control if this bar is shown by default or not
- Improve error handling of general HTTP errors with the same messages as
  during the login process
- Fix layout issue on iPad that prevented display of the login menu on the home
  document screen
- Attempted fixes for a number of concurrency issues in the document edit
  screen and during photo import
- Fix bug that prevented returning to the start screen after deleting a document
- Improvements to the animation during server switching
- Prepare for granular handling of user permissions
- Improved layout of the document detail screen for larger dynamic text sizes
- Fix for storage path not being added to newly created documents
- Fix ASN not being saved when uploading documents with restricted user accounts
- Reintroduce delay when typing search text
- If configured, remove inbox tags from documents automatically when saving
- Fix a bug during migration from single-server (v1.1.1 and before) to
  multi-server: the login token was not correctly persisted. This led to a
  connection error the next time the app was launched.
